> **定位**：跨期、跨城、跨区县的信息价 xlsx 分析工具
> **不与 `信息价提取/` 对接**：本项目是独立项目，互不依赖
> **作者**：用户 + Claude（2026-08-14）
> **当前时间**：2026-08-14 16:28（本会话延续，无跨天）

## §0 设计哲学（3 条原则）

| # | 原则 | 含义 |
|---|---|---|
| 1 | **造价语义 > 文本相似度** | "商品混凝土 C30" 和 "砼 C30" 是同一物（Jaccard 0.5 但语义同）；"C30" 和 "C40" 文本相似但语义不同（数字强保护） |
| 2 | **人工闭环 > 全自动** | 同义匹配不达阈值不进缓存，必进 `pending_pool.csv` 让人审一次，审完写库永久记住 |
| 3 | **空间插值 ≠ 时间预测** | 已知 A 区县价格 → 估 B 区县价格（IDW），不做"今年多少钱明年多少钱"的时间外推 |

---

## §1 一句话目标

> **输入任意结构的 xlsx 文件 → 输出 1 份 md 总报告**，覆盖：材料分桶 + 区间规格标称化 + 多期合并 + 同物匹配 + 4 类查询 + 空间插值（IDW），让造价员**只看 §0 摘要就能拿结论**。

**术语约定**：
- "预测" 在本项目中等价于 **空间插值**（IDW），不是时间序列预测
- "同物" = Jaccard ≥ 0.95 **且** 数字强保护通过（spec 数字集必须一致）
- "跨城对比" V1 只做成都 V1 单城；V2 再扩多城

---

## §2 核心规则（7 条硬约束）

| # | 规则 | 触发条件 | 处理方式 |
|---|---|---|---|
| 1 | **同名匹配必须先审后入库** | Jaccard 0.85–0.95 | 进 `pending_pool.csv`，人审 ✅/❌/✏️，回写 YAML 永久记 |
| 2 | **数字强保护** | 两 spec 数字集合不同 | 必判为不同物（哪怕 Jaccard 1.0） |
| 3 | **区间规格标称化** | spec 含区间（Φ8-10、Φ25.1-28） | 标称化：Φ8-10 → Φ9（中位数），Φ25.1-28 → Φ26.55（中位数），再比 |
| 4 | **价格列独立** | 一文件含 多价格列（含税/不含税/除税）| 每列分别分析，不互斥 |
| 5 | **空价格列剔除** | 价格列 100% 空 | 不作为依据，跳过 |
| 6 | **产地仅展示** | 含 产地列 | 保留原字符串，仅展示，不做地理推断 |
| 7 | **期数三级降级** | 文件期数未知 | L1 文件名 → L2 内部列 → L3 人工映射 |

## §3 已知数据坑（10 条）

| # | 坑 | 现象 | 处理 |
|---|---|---|---|
| 1 | 同名不同物 | "商品混凝土" vs "沥青混凝土" | 数字强保护 + 章节上下文 |
| 2 | 拼写变体 | "商品混凝土" vs "砼" | 同义词库 `material_synonyms.yaml` |
| 3 | 规格大小写/空格 | "C 30" vs "c30" | NFKC Unicode 归一化 + 去空格 + 大写 |
| 4 | 列标题歧义 | "参考价" "信息价" "市场价" | 智能列识别：选数据最多的列 |
| 5 | 单位变体 | "m³" vs "立方米" vs "M3" | `unit_synonyms.yaml` |
| 6 | sheet 名歧义 | "市场信息价" "金属材料" "商品混凝土" | 按 sheet 名优先级匹配 |
| 7 | 多版本期数 | 同一期有 v1/v2 重命名 | 优先取文件名期号，回退 xlsx 内部 |
| 8 | **规格含区间值** | Φ25.1-28cm、Φ8-10 | §2 规则 3 标称化 |
| 9 | **混凝土含附加信息** | "含三环路以内工地运输费" | spec 附加条件 → 元数据列，不参与匹配 |
| 10 | **价格含区间值** | 银杏 3200.00-5150.00 元 | 拆为 (low=3200, high=5150)，分别分析 |

## §6 期数三级降级提取逻辑

> **核心**：**Excel 元数据不参与期号判断**（Phase 0 验证 02-06 期错 2 次/5 次）。
> Excel 元数据仅写入 `excel_*_ref` 列展示，工具只用 `period` 列。

```
L1: 文件名正则（自动）
  正则: r'[\u4e00-\u9fa5]*第?\d{1,2}期'
  例: "2026年成都市工程造价信息价第4期.xlsx" → year=2026, period=04
  输出: period_source=L1

L2: 手动标注（hash 命名 fallback）
  触发: 文件名不匹配 L1（即 sha256 命名的 xlsx）
  方式:
    --interactive: 交互式逐个标注（推荐首次）
    --map "file=period,file=period": 命令行批量标注
  缓存: 3_中间产物/period_mapping.yaml（按 sha256 索引）
  输出: period_source=L2 (interactive 或 cmdline)

L3: manifest.csv escape hatch（任何时候）
  触发: 用户编辑 manifest.csv 改 period_source=L3
  输出: period_source=L3
```

**period_mapping.yaml 缓存格式**：
```yaml
period_mapping:
  abc123def456...:  # sha256(file_content)
    filename: "4bc506f3...xlsx"
    period: "05"
    year: 2026
    source: "L2_interactive"  # 或 L2_cmdline
    user_confirmed_at: "2026-08-14 17:00:00"
    excel_period_ref: "05"  # Excel 元数据参考（仅供参考）
    excel_month_ref: "5"
```

**manifest.csv 12 列**：
```csv
file_path,file_sha256,filename_period_source,year,period,city,sheet_name,row_count,excel_year_ref,excel_period_ref,excel_month_ref,notes
D:/.../04期.xlsx,abc123...,L1,2026,04,成都,市场信息价,3738,2026,04,3,文件名匹配
D:/.../4bc506f3.xlsx,def456...,L2,2026,05,成都,市场信息价,3896,2026,05,5,用户首次标注
```

**关键约束**：
- 工具下游 Phase 1/2/3/4 **只读 `period` 列**，不读 `excel_*_ref`
- sha256 索引：文件重新生成后 sha 变 → 重新问用户；其他文件缓存不变
- L2 标注一次永久记（HITL 闭环）

## §11 空间插值算法（IDW + 成都 17 坐标）

**目标**：已知 A 区县价格 → 估 B 区县价格（不做事时间外推）。

**前置数据**：成都市 17 个区县坐标（手工录入，一次性 < 30 分钟）。

```yaml
# coords/chengdu_districts.yaml
# 5 主城（锦江/青羊/金牛/武侯/成华）在数据里只出现在 "成都市" 综合行，
# 单独区县行没有这 5 个主城价格 → IDW 不可用，用综合行兜底
districts:
  # ===== 17 个有独立区县行的 =====
  龙泉驿区: {lat: 30.5564, lon: 104.2745}
  青白江区: {lat: 30.8836, lon: 104.2549}
  新都区: {lat: 30.8241, lon: 104.1586}
  温江区: {lat: 30.6796, lon: 103.8367}
  双流区: {lat: 30.5736, lon: 103.9235}
  郫都区: {lat: 30.8088, lon: 103.9019}
  都江堰市: {lat: 30.9884, lon: 103.6469}
  彭州市: {lat: 30.9901, lon: 103.9417}
  邛崃市: {lat: 30.4133, lon: 103.4644}
  崇州市: {lat: 30.6301, lon: 103.6713}
  # ===== Phase 0 补的 7 个 =====
  简阳市: {lat: 30.4012, lon: 104.5494}
  金堂县: {lat: 30.8580, lon: 104.4120}
  新津区: {lat: 30.4158, lon: 103.8117}
  大邑县: {lat: 30.5850, lon: 103.5218}
  蒲江县: {lat: 30.1980, lon: 103.5158}
  天府新区成都直管区: {lat: 30.4500, lon: 104.0500}  # 行政中心坐标
  东部新区: {lat: 30.2400, lon: 104.4500}
  # ===== 5 主城（仅综合行，无独立行，标占位）=====
  锦江区: {lat: 30.6586, lon: 104.0812}  # 综合行兜底
  青羊区: {lat: 30.6746, lon: 104.0617}  # 综合行兜底
  金牛区: {lat: 30.6938, lon: 104.0525}  # 综合行兜底
  武侯区: {lat: 30.6424, lon: 104.0648}  # 综合行兜底
  成华区: {lat: 30.6603, lon: 104.1011}  # 综合行兜底
```

**算法步骤**：

```
1. 按材料分桶（如 混凝土 C30）
2. 同桶内 spec 标称化（区间 → 中位数）
3. 对每个 spec 组:
   a. 找出所有已知区县价格（取各区县中位数）
   b. 对每个未知区县:
      - 算距离 d_i = haversine(未知, 已知_i)
      - 权重 w_i = 1 / d_i^p（p 默认 2）
      - 估算价 = Σ(w_i * price_i) / Σ(w_i)
      - 标记 "估算"，不出现在已知清单
4. 报告展示: 已知价 + 估算价（用颜色/前缀区分）
```

**§11 边界**（我提的修改）：
- V1 只录入**成都 17 坐标**（一次性 < 30 分钟，Phase 0 验证后录入）
- V2 再扩 6 城坐标（重庆/北京/广州/武汉/湖北）
- **5 主城（锦江/青羊/金牛/武侯/成华）单独无区县行**，用"成都市"综合行兜底

**回退方案**：
- 未知区县坐标缺失 → 标记 "IDW 不可用"，仅展示已知价格
- 已知区县 < 3 个 → IDW 结果标 "低置信度"

## §13 风险与边界

| 风险 | 边界 | 缓解 |
|---|---|---|
| 同物匹配错 | Jaccard 阈值经验值 | 0.85–0.95 进 pending 人审 |
| 区间规格误判 | 中位数 vs 平均数 | 默认中位数，spec 区分度高时改平均 |
| 产地信息利用率低 | 仅展示 | 用户撤回，不做地理推断 |
| 缓存膨胀 | 500MB 上限 + 3 版本保留 | 自动清理 |
| 多价格列混淆 | 每列独立分析 | 报告分列展示 |
| pending_pool 累积 | 人工成本 | 审过即写库，下次同 case 0 成本 |
| IDW 距离假设 | 直线距离 ≠ 运输距离 | 标记 "估算"，低置信度提示 |
| 6 城坐标未录入 | V1 只成都 | §11 边界明确 |
