# P0-5A 表单简化变更计划 v0.1

**状态：`PLAN_ONLY`**（审核通过前不修改代码）

## 0. 问题诊断

当前 P0-5A 补录表单将「数据库字段」直接暴露为「用户表单」，过重。表现：

| 问题 | 现状 | 影响 |
| --- | --- | --- |
| 必填项过多 | 10+ 字段全部必填（material_type / systemType / jurisdiction_level / jurisdiction_code / title / edition_year / edition_label / issuer_name / discipline_code 等） | 首次补录门槛过高 |
| 分册专业强制填写 | `discipline_code` 或 `discipline_label` 必须二选一 | 用户可能还不确定专业分类 |
| 英文字段名泄露 | 表单 label 中出现 `(material_type)`、`(edition_year)`、`(discipline_code)`、`(未命中字典 label)` | 暴露内部技术细节 |
| 法律状态要求用户选择 | 下拉框 `unknown/pending/effective/repealed` | 应根据日期自动计算 |
| 错误展示粗暴 | 底部红色大块列出所有技术错误 | 吓退用户 |
| 体系名称需要手填 | `title` 完全由用户输入 | 可从已有信息自动生成 |
| 分册创建需要手动操作 | 添加分册 → 选文件 → 填名称和专业 | 批量上传 PDF 后应自动创建分册 |

## 1. 设计原则

> **数据模型可以完整，但首次补录只问用户最少的信息，其余自动生成、后续核验。**

- **做减法**：首次补录只暴露 4 项必填，其余折叠或后置。
- **自动生成优先**：能用已有信息推断的，不由用户填写。
- **系统信息不泄露**：英文字段名、字典 code、校验错误堆栈等内部信息不展示给用户。
- **错误提示轻量化**：字段旁提示 + 底部计数，取代大块红色错误列表。
- **批量操作为默认路径**：拖入多个 PDF 时自动创建分册，而不是让用户逐个新建分册再逐个加文件。

## 2. 变更清单

### 2.1 首次补录仅保留 4 项必填

| # | 字段 | 说明 | 变更 |
| --- | --- | --- | --- |
| 1 | 定额体系 | `construction_regional` / `industry_specialty` | 保留，必填 |
| 2 | 地区或行业 | 建筑工程→地区（如 四川省），专业工程→行业（如 电网工程） | 保留，必填；**行政层级（全国/省份/地市）从一行字合并为下拉选项的前缀**，不再独立字段 |
| 3 | 年份 | 如 2025 | 保留，必填 |
| 4 | 至少一份正文文件 | 拖入或选择 PDF | 保留，必填 |

**体系名称（`title`）自动生成**，规则见 §2.2，生成后可修改。

### 2.2 体系名称自动生成规则

| 体系类型 | 生成模板 | 示例 |
| --- | --- | --- |
| 建筑工程定额 | `{地区名}{年份}建设工程计价定额` | 四川省2025建设工程计价定额 |
| 专业工程定额 | `{行业名}{年份}工程定额` | 电网工程2025工程定额 |

- 用户可点击名称行进行修改；
- 修改后即使用用户输入值，不再联动更新；
- 切换体系/地区/年份时若用户**未手动修改过**名称，则重新生成。

### 2.3 分册简化

当前流程：用户点「新增分册」→ 填分册名称 → 填 `discipline_code`（命中字典）→ 填 `discipline_label`（未命中字典）→ 选文件 → 选角色。

**改为**：

1. **批量上传 PDF 后，每个 PDF 默认生成一个分册卡片**；
2. **分册名称从文件名自动提取**（去掉 `.pdf` 后缀和编号前缀，如 `01_房屋建筑工程.pdf` → `房屋建筑工程`）；
3. **默认角色为「正文」（`main_document`）**；
4. **文件名含「附录」的自动识别为「附录」角色**（`appendix`）；
5. **分册专业允许「待识别」**，首次补录不强制填写；
6. 用户仅在识别错误时手工调整（改名称/改角色/拆分合并分册）。

### 2.4 「高级信息」折叠

以下字段全部收入 `<details>` 折叠区，默认不展开：

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| 资料性质 | `主定额` | `material_type = quota_base` |
| 版次 | 空 | 允许留空 |
| 发布单位 | 空 | 允许留空 |
| 发布日期 | 空 | 允许留空 |
| 实施日期 | 空 | 允许留空 |
| 标准/定额编号 | 空 | 允许留空 |
| 法律状态 | **自动计算** | 根据实施日期与当前日期比较：有实施日期且已过 → `effective`；有实施日期且未到 → `pending`；无实施日期 → `unknown`。**不要求用户选择**。 |

### 2.5 隐藏系统内部信息

以下内容**不再显示**在表单中：

| 移除项 | 原来位置 | 替代方案 |
| --- | --- | --- |
| `discipline_code` 独立输入框 | 分册卡片内 | 用户选专业时写 code（下拉从字典加载），但表单不暴露 code 输入框 |
| 「未命中字典 label」输入框 | 分册卡片内 | 专业选择器支持自由文本 + 字典下拉的 combobox；未命中时存入 `discipline_label_candidate` |
| 英文字段名 `(material_type)` / `(edition_year)` 等 | 表单 label | 纯中文 label |
| `jurisdiction_code` / `industry_sector_code` 文本框 | 体系路径区 | 下拉选择器（从字典加载），code 存入 state 但不展示 |
| 底部大块红色技术错误 | 弹窗 footer 上方 | 改为字段旁提示 + 底部计数（见 §2.6） |
| `Quota Compose · new_set` 的内部 action 名 | 弹窗 title 区 | 改为「新增定额」 |

### 2.6 校验与错误提示轻量化

**阻断提交的仅 4 种情况**（对应 §2.1 的四项必填）：

1. 未选择定额体系
2. 未选择地区或行业
3. 未填写年份
4. 没有正文文件（任何分册中都没有 `main_document` 角色的文件）

**错误展示变更**：

| 现状 | 改为 |
| --- | --- |
| 底部大块红色 `quota-compose-errors` 列表 | 缺失字段旁 inline 红色提示（如「请选择定额体系」）|
| 所有错误一次性列出 | 底部仅显示计数：**「还有 N 项必填信息未完成」** |

**分册级别的校验不再阻断提交**：
- 分册缺少正文 → 分册卡片内黄色提示「本分册缺少正文文件」，但不阻断提交；
- 分册多正文 → 分册卡片内黄色提示「多个正文文件」，但不阻断提交（用户可能在后续手工调整）；
- 分册无名称 → 自动从文件名生成，不出现缺失情况。

### 2.7 行政层级合并

当前：`行政层级` 独立下拉（全国/省份/地市）+ `地区编码` 文本框。

改为：**地区/行业下拉框中，选项自带层级前缀**：

```text
建筑工程定额 → 地区下拉：
  全国
  四川省
  成都市
  绵阳市
  ...

专业工程定额 → 行业下拉：
  电网工程
  水利工程
  铁路工程
  ...
```

选项来自 `QuotaDictionary`（`dict_type = 'jurisdiction'` / `dict_type = 'industry_sector'`），拉取时带层级标签。前端存入 `jurisdiction_code` / `industry_sector_code`，不再暴露 code 给用户。

### 2.8 批量上传交互

当前：每个文件通过分册卡片内的「添加文件」按钮逐个上传。

改为：**表单顶部放置拖拽区**，用户拖入多个 PDF 后：

1. 每个 PDF 创建一个分册卡片；
2. 分册名称 = 文件名去后缀；
3. 第一个文件默认 `main_document`，后续文件按文件名规则自动识别角色；
4. 用户可在分册卡片中手动调整。

拖拽区下方列出已识别分册，每个分册卡片内显示文件行（含自动识别的角色）。

## 5. 不变项（向后兼容）

以下行为保持不变：

- 草稿机制：`localStorage` 键格式、不存 File 对象、恢复标记 `missingContent` — **不变**
- 能力门控：五态模型、compose 未 ready 时仅允许本地草稿 — **不变**
- 域隔离：`#quotaShell` 独立渲染、`data-quota-action` 专属属性 — **不变**
- 四入口：新增清单规范 / 新建定额体系 / 向已有体系新增分册 / 向已有档案补充文件 — **不变**（但简化仅应用于"新建定额体系"入口；其他入口因交互不同，视情况简化）
- API 前缀：`/api/data-lake/quota/*` — **不变**
- 无 Mock / 无写死数据 — **不变**
- 六文件角色 — **不变**（但角色分配自动化）
