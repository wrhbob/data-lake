# pdf-page-extract — PDF 按页抽取并合并

## 0. 这个 skill 干啥的

把一个 PDF 中的**指定页面**(用页码规格字符串描述)**抽出 → 合并 → 写到一个新 PDF**。

适用场景:
- 信息价 PDF 抽样校验(从 132 页里抽 5-10 页送 OCR 试跑)
- 长文按章节切片(目录页 + 第 3 章正文 + 附录)
- 整本 PDF 拆出来后给另一流程 / 同事
- 不适用:需要 OCR、表格识别、文本提取 → 走 `cost-extract` 或 PDF2Markdown 流水线

## 1. 入口脚本

`pdf_page_extract.py`(本 skill 目录下)

```bash
PY=/d/miniconda3/envs/DLSE/python.exe
$PY .claude/skills/pdf-page-extract/pdf_page_extract.py <pdf> <pages> [-o OUTPUT]
# 或先 cd 到 skill 目录
$PY pdf_page_extract.py <pdf> <pages> [-o OUTPUT]
```

**依赖**: PyMuPDF(`import fitz`)— 项目 DLSE 环境已装。

完整输入输出规范见同目录 **`pdf_page_extract_SPEC.md`**(权威)。本文件只记"调用节奏"。

## 2. 何时调用

收到以下任一信号就触发:
- "把这份 PDF 的第 X 页抽出来"
- "抽 2-4 页 / 抽 2,5,7-9 页"
- "从 foo.pdf 切出这几页拼成一个小 PDF"
- "把 PDF 的目录页和第 3 章拼一起"
- 用户给出了 PDF 路径 + 一个页码规格(数字、`-`、`、`的混合)

不确定是否调用时:反问一句"你想要的是 PDF 页面级切片,还是文本 / 数据抽取?"。

## 3. 调用的最小信息

调用前必须向用户(或上一轮对话里)确认/索取:

| 字段 | 必填 | 说明 |
|---|---|---|
| PDF 路径 | ✅ | 绝对路径优先,相对路径请指明相对哪个目录 |
| 页码规格 | ✅ | 1-indexed,字符串,如 `2,4-5,7`(见 §4) |
| 输出路径 | ❌ | 缺省按 `<stem>_p<压缩序列>.pdf` 推到源 PDF 同目录 |

如果用户给的是"目录第 X 章"这种语义页(而非 PDF 物理页码),**先停下来跟用户确认**:本 skill 只支持物理页,不翻目录。

## 4. 页码规格语法(摘录,完整版见 SPEC.md §2)

| 写法 | 含义 |
|---|---|
| `2` | 单页 |
| `2-4` | 闭区间,等价 2,3,4 |
| `2,4-5,7` | 混合,逗号分隔 |
| `2, 4 - 5 , 7` | 容忍空白 |

- **1-indexed**(与 PDF 阅读器一致,不是 PyMuPDF 的 0-indexed)。
- **顺序保留**:输出页面顺序 = 输入 token 展开顺序。
- **自动去重**:重复页只保留首次出现。
- **闭区间**:`2-4` 含第 4 页。

## 5. 失败 → 0 输出(关键)

**只要规格里任何一页越界(超出 PDF 总页数 / < 1),脚本:**
1. stderr 报错并列出越界页号 + 合法范围
2. **不写任何输出文件**(即使其他 98 页都合法)
3. 退出码 `4`

这是用户强约定的"报错停止切分"语义,不要试图做"部分成功"。

## 6. 退出码速查

| 码 | 含义 |
|---|---|
| 0 | 成功 |
| 2 | 源 PDF 不存在 / 无法打开 |
| 3 | 页码规格格式非法(如 `2-`、`5-2`、`abc`) |
| 4 | 页码越界(关键防护点) |
| 5 | 抽取过程失败(已清理可能残留的半成品) |

完整表见 SPEC.md §4。

## 7. 调用范本

### 7.1 调用 shell 时

```bash
PY=/d/miniconda3/envs/DLSE/python.exe
PDF="D:/工程造价学习/Data/某市/某期.pdf"
SCRIPT=".claude/skills/pdf-page-extract/pdf_page_extract.py"

# 单页
$PY "$SCRIPT" "$PDF" "2"

# 区间
$PY "$SCRIPT" "$PDF" "2-4"

# 混合
$PY "$SCRIPT" "$PDF" "2,4-5,7"

# 显式输出
$PY "$SCRIPT" "$PDF" "2,4-5,7" -o /tmp/chunks.pdf
```

### 7.2 失败示例(预期表现)

```bash
# 假设某期.pdf 共 132 页
$PY "$SCRIPT" "某期.pdf" "2,200"
# stderr:
#   [错误] 页码超出范围: [200] 不在 [1, 132]
#     源 PDF 总页数: 132
#     合法范围: 1-132
#     不写任何输出文件,程序停止。
# 退出码: 4
```

## 8. 验收要点(调 Claude 时自查)

调用后,把脚本返回告诉用户:
- 输出 PDF 的**完整路径**(用户最容易忽略的)
- 抽出页数 + 源总页数(用户能据此判断"抽全了没")
- 退出码(若非 0,展示 stderr 关键行)

如果用户接着要做 OCR / 抽表,**主动接力**(PDF2Markdown/OCR 或 Markdown2CSV/extract.py),不要让用户自己拼。

## 9. 不要做的事

- ❌ 不要把页码规格中的 1-indexed 当成 0-indexed。
- ❌ 不要试图"部分成功"写出半成品。越界 → 0 输出是硬约束。
- ❌ 不要走 `pypdf` / `pdfplumber` 等其他库,统一 PyMuPDF(`fitz`)— 项目依赖一致。
- ❌ 不要"顺手"做 OCR、表格识别、文本提取,那不是这个 skill 的职责。
- ❌ 不要忽略用户的"区间闭 / 开"歧义 — 项目里一直用**闭区间**(`2-4` 含 4)。
