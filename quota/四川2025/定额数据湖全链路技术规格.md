# 定额数据湖:入湖 → 解析 → 应用 全链路技术规格

> 用途:本文档是给 Claude Code 的实现规格书。按模块分期实现,每个模块给出职责、数据契约、核心算法与验收标准。
> 领域背景:全国各省《建设工程工程量清单计价定额》(扫描版 PDF 为主)入湖,解析为结构化定额库,支撑"清单自动套定额"与市场化清单人材机组价。

---

## 0. 四条核心设计原则(所有模块必须遵守)

**P1 量价分离。** 定额的本体是消耗量。子目表只存消耗量,不存任何价格事实;价格是独立维度(省 × 价格期数 × 要素),基价/人工费/材料费/机械费一律是"消耗量 × 某期要素价"的**计算结果**。书上印刷的基价只入质检对照表,用作校验和。

**P2 工序桥。** 清单(结果导向)与定额(工序导向)不直接匹配。中间层是受控工序词表 + 两侧映射:清单项→标准工序集(来自清单规范"工作内容"栏),定额子目→工序(来自定额"工作内容"文本)。运行时 LLM 只做"抽取 + 归一到受控词表",不自由生成工序。

**P3 统一模型 + 省级 Profile。** 全国统一的子目 Schema 与要素主数据;各省版式差异(编号格式、表格样式、费用口径、计量习惯)全部收敛到省级解析 Profile 与口径标记字段,核心解析器、质检规则、语义索引全国复用。

**P4 确定性优先。** 硬坐标(清单编码前缀→章节)> 结构化槽位规则 > 向量语义。LLM 与 embedding 只出现在无法确定性求解的环节,且输出必须落到受控词表/结构化槽位,全程可解释、可审计,低置信度必须走人工复核出口。

## 1. 总体架构

```
Layer 0  档案层(数据湖入口)
  原件对象存储 + 档案元数据 + 版本族谱 + 覆盖矩阵 + 归档状态机

Layer 1  解析层(PDF → 结构化)
  页面渲染 → OCR/版面/表格识别 → 省级Profile结构化 → 要素对齐 → 交叉质检 → 落库

  要素主数据 | 工序词表 | 清单↔工序↔定额映射(桥) | 系数规则库 | 语义索引(embedding)

  清单行 → LLM特征解析 → 工序激活/抑制 → 桥查询 → 定额子目集(带换算)

```

## 2. Layer 0 档案层

### 2.1 数据模型(DDL)

```sql
-- 档案原件:入湖的最小物理单元(一个PDF文件)
CREATE TABLE archive_file (
  id            UUID PRIMARY KEY,
  sha256        TEXT UNIQUE NOT NULL,      -- 内容指纹,查重依据
  filename      TEXT,
  storage_uri   TEXT NOT NULL,             -- 对象存储地址
  page_count    INT,
  dpi_estimate  INT,                       -- 抽样页评估
  has_text_layer BOOLEAN,                  -- pdffonts 探测
  status        TEXT NOT NULL,             -- 状态机见 2.3
  uploaded_by   TEXT,
  uploaded_at   TIMESTAMPTZ DEFAULT now()
);

-- 定额册:业务单元(一省一专业一版本的一册),可对应多个archive_file(分卷/补充文件)
CREATE TABLE quota_book (
  id            UUID PRIMARY KEY,
  province      TEXT NOT NULL,             -- GB/T 2260 省级代码
  domain        TEXT NOT NULL,             -- 房屋建筑/装饰/安装/市政/园林/爆破...
  edition_year  INT NOT NULL,              -- 版本年,如 2020
  title         TEXT NOT NULL,
  doc_number    TEXT,                      -- 发布文号
  effective_date DATE,
  cost_scope    TEXT NOT NULL,             -- 费用口径: comprehensive(综合基价含管理费利润)
                                           --          | direct(仅人材机) | other
  superseded_by UUID REFERENCES quota_book(id),   -- 被哪个版本替代(版本族谱)
  book_kind     TEXT NOT NULL,             -- base(基准定额) | adjust(调价文件)
                                           -- | fee(费用定额) | mapping(清单定额对照) | errata(勘误)
  parent_book   UUID REFERENCES quota_book(id),   -- 调价/勘误挂到基准册
  parse_profile TEXT,                      -- 使用的解析Profile名, 如 sichuan_2020
  UNIQUE(province, domain, edition_year, book_kind, title)
);

CREATE TABLE book_file (          -- 册↔文件 多对多
  book_id UUID REFERENCES quota_book(id),
  file_id UUID REFERENCES archive_file(id),
  seq INT, PRIMARY KEY(book_id, file_id)
);
```

### 2.2 入湖流程(lake/ingest.py)

1. 上传 → 计算 sha256 → 命中已有指纹则标记 `duplicate` 并终止(对应界面"重复")。
2. 完整性探测:`pdfinfo` 页数、`pdffonts` 判断是否扫描件、抽样 3 页渲染评估清晰度(拉普拉斯方差 < 阈值则标 `abnormal`,对应界面"异常")。
3. 人工/半自动登记 quota_book 元数据(省、专业、版本年、文号、口径、book_kind),挂接 book_file。**cost_scope 与 book_kind 为必填,不允许默认值**——口径错了下游全错。
4. 建立族谱:调价文件 parent_book 指向基准册;新版本发布时旧版 superseded_by 指向新版。**旧版本不删除**(在建项目锁定旧版定额是常态)。
5. 状态置为 `registered`,进入解析队列。

### 2.3 归档状态机(lake/state_machine.py)

```
uploaded → registered → parsing → parsed → qa_passed → usable
     ↓          ↓           ↓        ↓         ↓
 duplicate   abnormal    parse_failed      qa_review(人工复核队列)
```

`usable`(可套用)的判定比"解析完成"更严:基准册 qa_passed + 至少挂接一个当期价格期数(§6)+ 清单编码映射表就绪(§5.2)。**覆盖矩阵每个格子显示的就是这个状态机的当前值**,前端据此着色。

**状态回退规则**:已 `usable` 的册收到新勘误文件(`book_kind='errata'`)或调价文件(`book_kind='adjust'`)挂接时,该册状态自动从 `usable` 回退到 `qa_review`,需人工确认勘误/调价的系数与要素对齐无冲突后方可恢复 `usable`。覆盖矩阵上对"有未处理勘误"的格子附加警告标记。

## 3. Layer 1 解析层

### 3.1 页面渲染与分类

`render.py`:PyMuPDF 按 300dpi 灰度渲染(扫描件本身 300dpi,1:1 不损失)。
`page_classifier.py`:基于 OCR 版面结果的规则分类器,每页归入:

- `cover_toc` 封面/目录/扉页 —— 跳过或仅提取目录做章节校验
- `chapter_title` 章节标题页 —— 更新章节游标,提取清单编码锚
- `notes` 说明/计算规则页 —— 进 note_parser
- `quota_table` 定额表页 —— 进 table_parser
- `appendix_price` 附录取定价表 —— 进 resource_align 建要素主数据锚
- `other`

分类特征:是否含 `工作内容[::]`、是否含定额编号模式(由 Profile 提供正则)、是否含"说明"/"工程量计算规则"标题、表格占版面比例。

### 3.2 省级 Profile(parser/profiles/)

每省一个 Profile 类,只允许包含**声明式差异**,禁止在 Profile 里写解析逻辑:

```python
class SichuanProfile2020(BaseProfile):
    code_pattern   = r"^[A-Z]{2}\d{4}$"        # AA0001
    chapter_pattern = r"^([A-Z]\.\d+(\.\d+)*)\s*(.+?)(?:[((]编码[::](\d{6,9})[))])?$"
    cost_scope     = "comprehensive"            # 综合基价: 基价=人+材+机+管理费+利润
    cost_rows      = ["综合基价","人工费","材料费","机械费","管理费","利润"]
    unit_position  = "table_header_right"       # "单位:100m3" 印在表右上
    resource_categories = ["人工","材料","机械"]
    watermark_chars = set("四川省住房和城乡建设厅信息公开浏览专用")
```

新接一省 = 写一个 Profile + 跑质检 + 修正,不改核心解析器。

### 3.3 定额表解析(table_parser.py,核心模块)

输入:PP-Structure 输出的表格 HTML(含 rowspan/colspan)+ 页面上下文(当前章节游标、最近的"工作内容"、单位声明)。

算法:

1. **HTML→网格展开**:解析 rowspan/colspan,合并单元格值向右/向下填充成矩形网格(已有参考实现,见附录 A)。
2. **行分区**:定位定额编号行,判定规则(宽松优先,避免单编号续表误判):
   - 行首含"定额编号"/"编号"字样且至少命中 1 个 Profile.code_pattern → 编号行
   - 或一行命中 ≥2 个 code_pattern → 编号行
   - 或命中 1 个 code_pattern 且上页表格未闭合(见 step 6 续表逻辑) → 编号行
   编号行之上为噪声、之下依次为 项目名称区 / 费用区 / 消耗矩阵区。费用区起点由 Profile.cost_rows 首项("综合基价"/"基价")锚定。
3. **列→子目**:编号行每个命中编号的列索引即一个子目列。项目名称区按列纵向收集去重的非空单元格,得到 `name_parts`(多级表头路径),拼接为 `name`。
4. **费用区**:按 Profile.cost_rows 逐行解析数值 → 写入 `qa_printed_price` 质检对照表(**不写业务表**,原则 P1)。
5. **消耗矩阵**:行首类别游标(人工/材料/机械)+ 每行 [名称, 单位, 单价, q1..qn],消耗量按列对齐到子目。单价同样只进质检表。
6. **跨页续表**:若本页表格无编号行但列数/列宽与上页表格匹配,且上页表格未闭合(无底边框特征或上页最后一行是消耗行),则拼接到上页表格续解析。章节游标、工作内容游标跨页保持。
7. **单位归一**:`10m3/100m2/1000块` 等解析为 `(基数, 标准单位)` 二元组存储;**消耗量保持书面原值**,归一换算只在组价时按基数进行,避免存储层引入精度损失。

输出契约(业务表):

```sql
CREATE TABLE quota_item (
  id            UUID PRIMARY KEY,
  book_id       UUID REFERENCES quota_book(id),
  code          TEXT NOT NULL,             -- AA0001(省内唯一,全国用 book_id+code)
  name          TEXT NOT NULL,             -- 拼接全名
  name_parts    JSONB NOT NULL,            -- ["人工挖一般土方","三类土","深2m以内"]
  unit_base     NUMERIC NOT NULL,          -- 10
  unit_std      TEXT NOT NULL,             -- m3
  work_content  TEXT,
  note          TEXT,
  chapter_path  JSONB,                     -- ["A.1 土石方工程","A.1.1 土方工程"]
  list_code_prefix TEXT,                   -- 章节印刷的清单编码锚, 如 010101(可空)
  source_page   INT,
  UNIQUE(book_id, code)
);

CREATE TABLE consumption (                 -- 消耗量: 定额的本体
  quota_id    UUID REFERENCES quota_item(id),
  resource_id UUID REFERENCES resource_master(id),
  quantity    NUMERIC NOT NULL,            -- 书面原值(对应 unit_base 个 unit_std)
  in_paren    BOOLEAN DEFAULT false,       -- 括号量(如柴油(24.718), 不计价只备查)
  PRIMARY KEY(quota_id, resource_id)
);

CREATE TABLE qa_printed_price (            -- 印刷价格: 仅质检用
  quota_id UUID, field TEXT,               -- base/labor/material/machine/manage/profit
  printed  NUMERIC, PRIMARY KEY(quota_id, field)
);
```

### 3.4 章节说明解析(note_parser.py)

说明文本按原则拆三类产物,LLM 辅助分类 + 规则抽取,产物必须结构化:

**① 适用范围/项目界定** → `chapter_note(chapter_path, kind='scope', text)`,原文入库,参与该章节子目的语义坐标文本(§5.4)。

**② 系数规则** → 结构化为可执行规则:

```sql
CREATE TABLE coeff_rule (
  id UUID PRIMARY KEY,
  book_id UUID, chapter_path JSONB,
  trigger JSONB NOT NULL,   -- {"slot":"depth","op":">","value":6,"unit":"m"}
                            -- 或 {"condition_text":"挖淤泥流砂","slot":"soil_class"}
  action  JSONB NOT NULL,   -- {"multiply":1.10,"apply_to":["labor"],"base_item_hint":"深6m项目"}
                            -- apply_to: all|labor|material|machine
  scope   JSONB,            -- 作用的子目范围: 章节/编号区间/名称模式
  source_text TEXT NOT NULL -- 原文, 审计用
);
```

抽取用 LLM,prompt 契约:输入说明条文,输出上述 JSON 或 `{"not_a_rule": true}`;**每条规则必须带 source_text 且经人工确认后才置 active**(初期全量人审,积累后抽检)。

**③ 工程量计算规则** → `chapter_note(kind='calc_rule')`,原文入库,套定额时仅用于单位/口径提示,不参与自动执行。

### 3.5 要素对齐(resource_align.py)

```sql
CREATE TABLE resource_master (             -- 全国人材机要素主数据
  id        UUID PRIMARY KEY,
  category  TEXT NOT NULL,                 -- 人工|材料|机械(机械=台班级,原则上不再展开)
  name_std  TEXT NOT NULL,                 -- 标准名: 预拌混凝土
  spec_std  TEXT,                          -- 标准规格: C30
  unit_std  TEXT NOT NULL,                 -- m3
  province_scope TEXT DEFAULT 'national',  -- 省专属要素标记省份
  aliases   JSONB DEFAULT '[]',            -- 已确认的书面变体
  UNIQUE(category, name_std, spec_std, unit_std, province_scope)
);
```

对齐流程:优先解析该册附录"人工、材料、机械台班单价取定表"作为该省要素全集锚 → 正文消耗行按 `规范化(去空格/全半角/单位同义)` 精确匹配 → 未命中走 `字符n-gram相似 + 单位一致` 候选,相似度 ≥0.92 自动挂接并追加 alias,<0.92 进人工对齐队列。**机械展开到台班一级为止**;台班内部构成(油耗/折旧)作为可选第二层,P2 之后再做。

### 3.6 交叉质检(qa.py)——本书自带校验和

对每个子目执行:

```
计算基价 = Σ(consumption.quantity × 附录取定价[resource_id])  (+ 按口径加管理费利润)
diff = |计算基价 − qa_printed_price.base|
```

- diff ≤ 0.05 元(舍入容差):PASS
- diff > 容差:定位到具体环节——先校验人工费分项(只涉及人工要素,变量少),再材料、机械,输出"疑似 OCR 错误字段 + 页码 + 裁剪图"进人工复核队列。
- 附加检查:编号断号检测(AA0001..AA000n 连续性)、章节路径异常(层级跳变)、单位缺失、消耗矩阵空列。

质检指标落表,册级汇总:
- **分母** = 册内可完成基价校验的子目数(排除因附录取定价缺失或要素未对齐而无法校验的子目,但仍计入断号/章节异常等结构检查)。
- **分子** = 通过所有校验项(diff≤0.05 元且无结构异常)的子目数。
- `qa_pass_rate ≥ 99%` 且复核队列清零方可 `qa_passed`。
- 因取定价缺失而跳过的子目单独列 `skipped_qa` 清单,需人工确认取定价来源。
**这条流水线的人工工作量应集中在质检标红项,而非全量校对。**

## 5. Layer 2 语义资产层(套定额的准备)

### 5.1 受控工序词表(process_vocab.py)

```sql
CREATE TABLE process_term (
  id UUID PRIMARY KEY,
  term TEXT UNIQUE NOT NULL,        -- 受控词: 土方开挖 / 基底钎探 / 场内运输 / 模板安拆
  aliases JSONB DEFAULT '[]',       -- 挖土|开挖土方|挖运土方(激活匹配用)
  domain TEXT,                      -- 土建/装饰/安装...
  granularity_anchor TEXT           -- 说明: 粒度锚定在定额子目工作内容一级
);
```

种子来源:清单规范(GB50500 及新国标)每个清单项的"工作内容"栏 → 人工整理为受控词;定额工作内容解析时补充。**粒度铁律:与定额子目工作内容同级**(消耗量在该粒度核定,再细无数据支撑,再粗分不开子目)。

**候选下发策略(防止 prompt 膨胀):** 套定额时不下发完整工序词表,只下发该清单项 9 位编码对应的桥 1 默认工序集(通常 3–8 条)的 `term + aliases`,再加 1 条标记 `"other_reject": true` 约束 LLM 不自由生成工序。如需激活桥 1 未包含的工序(由项目特征触发),在请求中显式追加候选。

### 5.2 三张桥表(bridge.py)——一等公民,静态资产,可人工修订,全量带来源

```sql
-- 桥1: 清单项 → 标准工序集(来自规范, 全国统一)
CREATE TABLE listing_process_map (
  listing_code TEXT NOT NULL,        -- 清单9位项目编码, 如 010101002
  process_id   UUID REFERENCES process_term(id),
  is_default   BOOLEAN DEFAULT true, -- 规范默认包含
  source TEXT NOT NULL,              -- 'GB50500-2013附录A' 等
  PRIMARY KEY(listing_code, process_id)
);

-- 桥2: 定额子目 → 工序(解析定额"工作内容"得到, LLM归一到受控词, 人审后active)
CREATE TABLE quota_process_map (
  quota_id   UUID REFERENCES quota_item(id),
  process_id UUID REFERENCES process_term(id),
  source_text TEXT NOT NULL,         -- 原文"挖土、抛土、修理边底"中的片段
  status TEXT DEFAULT 'auto',        -- auto|confirmed
  PRIMARY KEY(quota_id, process_id)
);

-- 桥3: 清单编码 → 定额章节(硬坐标; 印刷锚自动建, 无锚省份人工建, 独立维护)
CREATE TABLE listing_chapter_map (
  listing_code_prefix TEXT NOT NULL,  -- 6位
  book_id UUID, chapter_path JSONB,
  source TEXT NOT NULL,               -- 'printed'(书上印的) | 'manual' | 'companion_doc'
  PRIMARY KEY(listing_code_prefix, book_id)
);
```

**工程量换算挂在桥的边上**:

```sql
CREATE TABLE qty_conversion (
  listing_code TEXT, process_id UUID, quota_id UUID,
  factor NUMERIC,                    -- 简单系数: 清单量×factor=定额量(已含单位基数换算)
  formula TEXT,                      -- 复杂换算表达式(如需辅助工程量), factor为空时用
  aux_qty_required JSONB             -- 需要的辅助量: ["模板接触面积"]
);
```

### 5.3 特征槽位抽取(共享规则库)

正则规则集(全国共享,持续扩充):soil_class(土壤/岩石类别)、depth/thickness/height/diameter(带"以内/以外"区间语义)、strength(C30/M10/MU10)、method(人工/机械/泵送/现浇/预制)。范围槽位匹配实行**最紧界优先**(1.8m 套"2m以内"优于"4m以内",评分加紧致度奖励)。参考实现见附录 A。

### 5.4 语义索引(semantic_index.py)

每个 quota_item 的软坐标文本模板:

```
{chapter_path 拼接} | {name} | 单位:{unit} | 工作内容:{work_content} | {所属章节 scope 类说明摘要}
```

bge-large-zh-v1.5 编码,pgvector 存储,索引键含 (province, edition_year) 便于候选池过滤。**embedding 空间全国共享**(清单规范全国统一,语义一致),省级化的只是过滤条件与系数规则库。

## 6. Layer 3 应用层:清单套定额运行时

### 6.1 主流程(matcher.py)

```
输入: 清单行 {项目编码, 项目名称, 项目特征描述, 计量单位, 工程量}
     + 上下文 {省份, 定额版本, 价格期数链, 合同约定}

Step 1  LLM特征解析(listing_parser.py, 契约见§7)
        → {对象, 激活工序[], 抑制工序[], 部位参数槽位{}, 合同约定[]}
Step 2  标准工序集 = 桥1[编码前9位] ;应用激活/抑制 → 目标工序集
Step 3  候选池 = 桥3[编码前6位]→章节 → 该章节子目(硬过滤, 失败则退全册)
Step 4  对每个目标工序: 候选池 ∩ 桥2[工序] → 语义相似召回TopN → 槽位精排
        → 该工序最优子目(带 semantic_sim, slot_hits, 紧致度)
Step 5  覆盖度校验: 未覆盖工序 → 若市场化清单走6.2; 否则标记缺口
        多余候选(候选覆盖了未激活工序) → 丢弃并记录
Step 6  系数后处理: 遍历 coeff_rule, trigger 与槽位/特征比对, 命中则生成
        {子目, 系数, 作用费用项, 依据原文} 调整项
Step 7  工程量分解: qty_conversion 换算各子目定额量(缺辅助量则挂"需补量"标记)
Step 8  组价: pricing.compose 按期数链取价 → 清单综合单价 = Σ(子目量×子目单价调整后)
Step 9  输出(契约见6.3): 每工序Top-3候选+置信度+命中依据; 综合置信度<阈值 → 复核队列
```

置信度合成:`0.5×语义相似 + 0.3×槽位得分 + 0.2×工序匹配完整度`,阈值初设 0.65,复核数据回流后校准(预期成熟期阈值在 0.65–0.75 之间,初期 0.65 平衡"自动通过率"与"宁可多复核不可套错"偏好)。

### 6.2 市场化清单分支

无定额覆盖的工序 → 查企业消耗模板表(结构与 consumption 完全同构,book_kind='enterprise'):命中则直接人材机组价(要素价格同一套 resource_price);未命中 → LLM 生成人材机构成**草案**(要素必须归一到 resource_master,禁止自由文本)→ 人工确认 → 沉淀为企业消耗模板。**这条回流是企业定额的积累飞轮,确认动作必须留痕。**

## 7. LLM Prompt 契约(apply/listing_parser.py)

系统约束:输出严格 JSON;工序只能从提供的受控词表候选中选(按 §5.1 候选下发策略,仅下发该清单项桥 1 默认工序集,不下发全量词表);不确定时输出 `"uncertain": true` 而非猜测。

```
输入: {项目编码, 项目名称, 计量单位, 项目特征描述原文, 候选工序词表}
输出: {
  "object": "一般土方",                    // 施工对象
  "activate": ["土方开挖","基底钎探"],      // 激活工序(仅限候选词表)
  "suppress": [{"process":"场外运输","evidence":"弃土运距自行考虑"}],
  "slots": {"soil_class":"三类土","depth":"1.8m"},   // 部位/参数槽位
  "contract_terms": ["弃土运距自行考虑"],   // 其他合同约定
  "uncertain": false
}
```

对拍要求:LLM 抽取的 slots 与 §5.3 正则抽取结果做一致性对拍,冲突时以正则为准并记录分歧样本。

## 8. 分期实施与验收标准

**P0 单省打通(四川2020房建册)**:Layer 0 状态机 + 解析管线 + 质检。验收:全册子目解析,qa_pass_rate ≥ 99%,基价校验和机制运转,复核队列可用。
**P1 量价分离**:附录取定价入库 + price_period + compose 接口 + 一份人工费调整文件挂接生效。验收:改一期人工价,任意子目重算价正确,零子目回写。
**P2 语义资产**:工序词表(土建域)+ 三张桥表(四川)+ 系数规则库(土石方章)+ 语义索引。验收:桥表全量带 source,系数规则人审通过率统计就绪。
**P3 套定额运行时**:6.1 全流程 + 降级出口 + 输出契约 + 复核回流。验收:土石方章测试集(≥200 条真实清单行)工序级 Top-1 准确率 ≥ 90%,need_review 召回了 ≥95% 的真实错误。
**P4 横向扩省**:第二个省(建议选编号/口径差异大的,如山东或广东)只新增 Profile + 桥 3 人工映射。验收:核心解析器零修改,新省达到 P0 同等质检指标。

通用红线:任何自动产物(工序映射、系数规则、要素对齐、企业消耗模板)在人工确认前不得进入 `usable` 路径;所有映射与规则必须带 source 字段可溯源到原文页码。
