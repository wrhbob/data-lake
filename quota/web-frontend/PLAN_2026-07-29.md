## §3. 主界面 UI 不完善（解析 / 下载 / 预览 三件套）

**现状**：档案列表行只有「预览」按钮（一个 icon），没有「解析」「下载」按钮。后端 `quota_api.py` 已有 7 个端点（parse / reviewed / preview / candidate / final / manifest / qa_report），但前端没挂。

### 3.1 按钮 → 端点对应表

| 按钮 | 端点 | 触发条件 | 行为 |
|---|---|---|---|
| 预览 | `GET /api/data-lake/quota/archives/{id}/preview` | 永远可点 | 新窗口打开 PDF blob URL |
| 解析 | `POST /api/data-lake/quota/archives/{id}/parse` | `parse_status in (None, 'failed', 'rejected')` | 启 task A，弹 toast「已提交解析」 |
| 查看候选 | `GET /api/data-lake/quota/archives/{id}/candidate` | `parse_status in ('parsed', 'qa_passed', 'qa_rejected')` | 下载 candidate.xlsx |
| 审定（mock B） | `POST /api/data-lake/quota/archives/{id}/reviewed` | `parse_status == 'parsed'` | 直接走 mock 阶段 B |
| 查看定稿 | `GET /api/data-lake/quota/archives/{id}/final` | `parse_status == 'qa_passed'` | 下载 final.xlsx |
| 查看 Manifest | `GET /api/data-lake/quota/archives/{id}/manifest` | 任何有 task_id | 弹 modal 看 JSON |
| 查看 QA 报告 | `GET /api/data-lake/quota/archives/{id}/qa_report` | `parse_status == 'qa_passed'` | 弹 modal 看 summary |

### 3.2 UI 改造

- 列表行「操作」列：从单按钮扩成「预览 / 解析 / 候选 / 审 / 定稿」5 个 icon button，按状态灰显
